## Abuse protections — 2026-10-22

Application release `071c636d9e837f839ce4a5a78aa277f74d5671051bfe33c38c6e9203d8cab5d8` adds 120 reads/minute/IP independently for the lobby, status and health endpoints, 12 simultaneous game/probe sockets/IP, and four human or spectator seats/IP across the process. Reconnect reservations count as seats, and Ping/Pong now consume the 150-frame/second connection budget. Canonical addresses and trusted viewer forwarding prevent equivalent-address or spoofed-prefix quota bypasses. People sharing one public address share these limits. The guarded empty-lobby installation preserved the existing four Oregon rooms and disabled overseas configuration; SQLite integrity, identity salt, all 61 pre-existing human credentials, record counts and backups passed verification with no new persistence, replication or panic errors.

The standalone `bolts-abuse-protection` stack in `us-east-1` attaches WebACL `bolts-api-abuse` to API distribution `E1MT909KTPVXKW`. Three production rules count actual viewer IPs over 60-second windows: 600 API requests, 120 combined session/join/game/probe handshakes, and 20 feedback POSTs. URI decoding and normalization protect equivalent paths. Responses use HTTP 429, retry guidance and browser CORS headers. The temporary QA rule and IP set were removed after verification; the final stack has only these three rules. The production rules use 42 WCU and cost approximately $8/month plus $0.60/million requests. This adds HTTP abuse controls to existing CloudFront/Shield protection; it does not verify human users or prevent all distributed automation. See [scope, thresholds and operations](../server/README.md#abuse-protection-and-verification).

Verification passed 150 Rust tests, 32 top-level Go race tests (69 including subtests), 627 frontend tests and the frontend build, 18 WAF/helper tests, and eight new deployment-preservation tests. Live spectator checks joined all four Oregon rooms, rejected the 13th socket and fifth seat, verified quota release, observed directory 429/Retry-After, and confirmed independent health/status. Chrome reached live Deathmatch and 1v1 Alpha spectator gameplay; the latter was verified with WAF attached. A temporary rule restricted to one tester IPv4 address and random unused path produced an edge-marked 429 on request 18, with normal health and preflight requests unaffected. WAF enforcement is approximate; this proves actual edge blocking, not an exact production-rule request threshold or sustained attack capacity.

The backend was built from the reviewed snapshot in `temp/abuse-protection/source/`, separately from concurrent gameplay changes; binary/source provenance and all local/live results are under `temp/abuse-protection/`. [deploy-abuse-backend.py](../scripts/deploy-abuse-backend.py) pins the previous release and uses the existing backup/rollback installer. [deploy-abuse-protection.py](../scripts/deploy-abuse-protection.py) preserves the full CloudFront configuration and guards its ETag. The association is intentionally outside the original backend stack template: future infrastructure updates and migrations must preserve its live `WebACLId`, and the backend deployment helper now refuses accidental removal.
